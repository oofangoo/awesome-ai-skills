# Higgsfield Video Production

Carry an authorized brief through the appropriate Higgsfield route to actual reviewed media. Keep technical validity, creative review, user acceptance and publication separate. This skill adds project continuity, route selection and quality control; it does not replace current tool schemas or existing specialist production skills.

## Recover the task and choose the route

Read the current brief, shot prompts, relevant project instructions and existing job/output records. Preserve the requested style, duration, references, budget and current authorization. A request to plan, quote, inspect or review is not a new generation request. Reuse completed work and recover in-flight jobs before creating replacements.

Read [access-and-cost.md](references/access-and-cost.md) before generation or selecting an access route. Honor an explicit browser or tool choice; otherwise prefer an available official connector with the required capability. A browser-only task must not silently become a paid API task because the browser is unavailable. Web Unlimited is a manual route under the provider's current rules, not a free automated backend.

For named Higgsfield slash commands/presets, use the available Higgsfield router first. For an end-to-end narrated film, song or specialized advertising workflow, use its appropriate installed skill when available while retaining this brief's constraints. Ordinary shot generation does not require inventing a preset or starting an unrelated pipeline.

## Preflight the actual request

Inspect the live model/interface controls for duration, aspect ratio, resolution, audio and supported media roles. Prefer the user's selected model; explain an incompatibility instead of silently substituting another. Do not maintain a fixed catalog of model IDs or advertised prices in this skill.

Inspect the reference images/videos and bind each to its confirmed role. Verify visible thumbnails and slot assignments against the brief, particularly after reusing a form: a leftover character image can undermine an otherwise correct prompt. Filling a prompt box alone does not set duration or reference mode.

For automated credit routes, obtain a current quote using the selected settings and budget. Some estimate tools import HTTPS reference media; inspect their current description before using them. Treat those imports as uploads within the user's asset scope. Honor existing approval and any tool-specific confirmation. Seek only missing spend authority; never convert a zero-credit request into paid generation or start a purchase/renewal.

Save a compact project run record using [run-record.md](references/run-record.md) and the [record template](assets/run-record.json). Do not store credentials or entire account pages. Keep the prompt, references, settings, quote/authority evidence and output versions identifiable.

## Submit or hand off, then reconcile

For a supported automated route, submit only the authorized request. Record the returned job ID and status immediately. Use documented status/result tools for that job until it reaches a terminal state; allow independent authorized work while waiting.

For manual website generation, deliver the exact prompt, local reference files and control checklist. The user performs the manual flow required by the provider. Resume from the real job/result they supply; a handoff or a button click is not confirmation that a render started.

For browser work that is permitted for the chosen task, use the user's requested browser. Discover the current browser tools and read their returned documentation rather than embedding a bootstrap path, selectors or coordinates here. Follow visible UI state. If unavailable, keep the useful local handoff and state the access gap; do not control an external desktop browser as a substitute.

A lost submission response is an unknown outcome. Reconcile native history, job IDs, supported idempotency and existing files before retrying. After one unresolved ambiguity or a repeated unchanged failure, stop new submissions and report the precise blocker. A definite failure may be revised within the remaining authorized budget; distinguish a retry from a newly paid generation. Respect provider queue limits and backoff signals without disguising automation as human activity.

## Download, review and revise

Retrieve the completed result through the supported route. Match it to the job and prompt; do not select an adjacent history thumbnail merely because it looks similar. Preserve the source export and make edits as versioned files. Use [review-and-recovery.md](references/review-and-recovery.md) for technical checks, full playback, decisive-action inspection and targeted revisions.

The bundled `scripts/review_video.py` performs nondestructive local technical checks and extracts review frames. It cannot watch, listen, judge creative success or grant user acceptance. Run it when that evidence is useful, not as a substitute for reviewing the output.

For a stockpile, keep one row per concept/version and its real acceptance state. Review the principal motion risk before duplicating a failing technique. Do not trade all remaining allowance for unreconciled or unreviewed jobs. Use the authorized count and provider's actual concurrency limits rather than a universal batch size.

Deliver the actual playable result or supported preview, with a short verdict, important defects and remaining work. State if only a prompt pack, queued render, partial review or user handoff was achieved. Publishing to a social account and scheduling future work are separate tasks with their own current authorization; creating video skills does neither.

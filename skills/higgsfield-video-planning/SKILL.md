# Higgsfield Video Planning

Turn a video idea into a brief another operator can execute without guessing the intended story, inputs or finish criteria. Works across narrative, documentary, visual comedy, product and illustrated projects; do not import one channel's style into another.

## Establish the project

Read the user's current request, applicable project instructions and the most relevant existing brief, acceptance record and reference media. For continuing work, search the project's notes or the user's knowledge base before asking them to repeat decisions. Prefer current artifacts over older summaries. Save working plans in the project, not this skill folder.

Recover the purpose, intended viewer, delivery format, total duration, visual style, language, audio, reference roles, requested model, budget and authorized scope. Resolve consequential gaps; use stated assumptions for routine creative choices. Keep claims about live models, limits, prices and entitlements unverified until checked through current official tools or documentation. An existing web subscription does not establish an automated generation budget.

Select the actual production form: fully animated action, live-action appearance, narrated scenes, still illustration, or an intentionally diagrammatic explanation. When the user asks for convincing generated action, plan observable performances and camera work. Do not replace it with diagrams or a still-image pan. Conversely, do not force animal slapstick or constant camera movement into a calm explainer.

## Develop a producible idea

For an open brief, offer a small set of meaningfully different mechanisms and recommend one. For an already chosen idea, develop it directly. State the viewer's question or character's objective, the change that drives the scene and the ending that resolves it. For factual content, identify claims requiring evidence before locking narration.

Design the hardest causal transition explicitly: what changes first, what force or decision causes movement, where each subject travels, what the camera can see and what remains at the end. Use distinct identities and exact prop counts when continuity depends on them. Budget time for the payoff and reaction rather than adding actions merely to fill the duration.

For a series, vary the actual mechanism and ending. Keep useful visual continuity without repeating the same collision, camera trick or plot. A user's accepted example is a creative reference, not evidence that the format will grow an audience.

## Build the handoff

Use [plan-format.md](references/plan-format.md) for the minimum handoff fields and a reusable shot record. Read [prompt-design.md](references/prompt-design.md) when writing timed action or reference-heavy prompts. Produce:

- A concise creative brief with constraints, assumptions and unresolved dependencies.
- A timeline or shot table whose intervals cover the requested duration, with continuity across shot boundaries.
- Copy-ready prompts and an explicit map from each supplied reference to its intended role.
- Planned UI/tool settings, a route and budget note, and concrete technical and creative review criteria.

Set duration, resolution, aspect ratio and reference slots in the actual generation controls during production; prompt wording is not proof those settings are applied. Check the selected model's live capabilities before promising an executable setting. If they are not available, leave a clearly marked dependency or explain a supported option without silently changing the brief.

For a technically uncertain batch, identify a representative pilot that tests the main risk before duplicating it. This is a production choice within the user's scope, not a reason to add an unnecessary approval checkpoint.

Return a usable plan and the next concrete action. Preserve existing authorization; planning does not grant permission to spend credits, buy a plan or publish. Use the companion `higgsfield-video-production` skill when execution is requested and it is available.
